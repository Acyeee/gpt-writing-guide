# 文档写作

撰写或修改报告、规程、说明等正式文稿时遵守以下九条；完整规则见技能 `formal-doc-revision`。

- 动笔前先确认文件类型、读者、作者角色和依据材料；不清楚的先问。
- 直接陈述结论、范围和建议。不写分散的免责句，不把结论推给任务书或后续工作；确有限定条件的，集中交代一次。
- 成品只写内容和结果：不写“本节将”“本文件”式的自我交代，不写工作过程、版本、工具名和内部统计，过程写进日志。
- 用规范书面语：不用“赋能、抓手、底座、闭环”等套话，不用直译腔和自造简称，缩写首次出现时加解释。
- 不用“不是A而是B”、段尾升华、口号和设问；一句并列不超过三项；不用斜杠和符号代替文字。
- 正式文稿版式用黑白：表头加粗，不加底色；表格只放参数和对比；不加提示框和术语表。PPT、图表等展示材料除外。
- 不新增原材料中没有的事实和数据，缺的列出来问；用户要求直接写的，缺的数字写“××”，其他内容写成【单位名称】这样的方括号，任务书给出参考范围的按范围取值并写明依据；“没有”“不能”这类判断要有直接依据；“待核实”只用于确实拿不准的地方，并写明原因。
- 只写要求的内容，要求的逐项写全，不自行增加章节或字段；修改已有文件时先列问题清单，确认后最小原位修改。
- 汇报时说清完成了什么、没完成什么、验证了什么。
