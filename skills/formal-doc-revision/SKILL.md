# 正式文稿写作与修改（针对 GPT/Codex 初稿）

完整经验和实例见同目录 `GPT文稿写作与修改经验.md`，开始前先读一遍。优先级：当前任务的明确要求 → 项目或期刊的专门规范（AGENTS.md、CLAUDE.md、写作规范等） → 本技能。各领域的文体和格式按该领域规范处理。用于科研论文时，先读参考文件第六部分：限定语与证据强度相称，方法写清过程，逐条核对文献真实性。开题报告、申报书、新闻报道、工作总结先读第七部分对应条目，冲突时以该条目为准；已有初稿的仍按下面的修改流程，条目只作检查要点。

## 撰写新文稿

1. 动笔前确认文件类型、读者、作者角色和依据材料；不清楚的先问，有第七部分条目的按条目中的问题问；用户已给出的信息不再重复问，信息够用就直接写。用户没有具体想法或要求直接写的，按第七部分（一）给出完整初稿，缺的内容空出来，不编造。
2. 先给出提纲和对任务的理解，确认后再写；用户要求直接写的，跳过这一步。
3. 按参考文件第一部分的九条写作约束撰写。
4. 写完按参考文件第五部分自查清单检查后交付；有空出内容的，需补充的清单写在交付说明里，不写进文稿。

## 修改已有文稿

两种模式：

- **单段文字**：直接修改，保留原意和合理结构，简要说明主要变化。
- **完整文件**：按下面的流程执行。无法判断时按这一种处理。

1. **确认目标**：确认要改哪份文件；读项目规范。
2. **定位**：文件类型、读者、作者角色、已有材料。由此决定哪些规则适用，例如技术说明中的脚本和日志属于正文，不按“过程性语言”处理。
3. **诊断，不改文件**：通读后输出问题清单（位置｜原文｜问题类型｜建议改法），分三层标注：表述层（参考文件第二部分八类问题）、逻辑层、事实层。逻辑层和事实层重点看三处：推断过头（少见就写成“没有”）、前后不一致（数字、判断、口径）、越出职责（替别人下结论、引用自己没有的数据）。逻辑和事实问题只列出，不擅自改写。结构性调整单独列出，请用户选择；缺失的数值列出来问用户。
4. **用户确认后最小原位修改**：只改有问题的句子；不做机械批量替换。
5. **自查**：按参考文件第五部分逐条检查。
6. **交付**：默认出审阅版（改动标蓝）和修改说明，定稿后再出干净版；用户另有要求的按用户要求。

审查 GPT/Codex 的任务产出（指令迭代、资料整理、运行结果）时，对照参考文件第三部分：范围扩张、只改不验、悄悄改条件、用“待核实”兜底、编造补全、改动越界、复述走样、汇报含糊。

## 八类问题速查

1. **防御性表述**：分散的免责句、“仍需验证”、把依据推给任务书、把结论推给后续、用“需复核”带过分歧、同一限定逐条重复、文件自我免责。
2. **自我指涉**：“本节将……”“下表总结了……”、说明框、提示框。
3. **过程与内部信息**：工作过程、版本状态、内部统计、工具名。
4. **形式堆砌**：处处用表格、斜杠并列、符号代替文字、超过三项的并列、口号、术语表；彩色表头（如深蓝底白字）、彩色字、带底色的提示框。
5. **AI 腔与自造词**：套话、直译腔、自造简称、口语词、未解释缩写。
6. **句式模板**：“不是A而是B”、路标词堆叠、段尾升华、设问、口号式收尾。
7. **口吻错位**：以“调研”“材料”作主语转述、越位给别人定规矩、第一人称辩护、换词不换口吻。
8. **结构重复**：同一内容多处出现、各分节重复公共内容、章节互相重复。

## 不要做

- 不照搬通用“去 AI 味”技能的口语化建议（加语气词、口语连接词、避免书卷气）。正式文档要规范书面语，“朴实”不等于口语化。
- 不新增原材料中没有的事实和数据，不编文件编号、批准人、参数阈值。
- 不把不确定的内容写成确定的；不删除数值本身的条件和有实际约束的限定语。
- 不把词表当禁词表：语境中自然、准确的词保留。
- 不为追求句式变化打乱规范结构。
- 定稿前不出干净版。
